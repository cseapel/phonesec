Developer Handoff

PhoneSec

Privacy watchdog for Android. Detects which apps access your microphone, camera, location, keyboard, Wi-Fi and Bluetooth — and surfaces silent background access via a floating chat-head alert.

1. Architecture

Stack

  • Kotlin + Jetpack Compose
  • Material 3, edge-to-edge
  • Min SDK 30 (Android 11), Target SDK 34
  • Room (local-only event log)
  • Foreground Service for monitoring
  • Bubble API for chat-head alerts

Modules

  • :app — UI, screens, Compose
  • :data — Room, repositories
  • :monitor — AppOps polling, foreground service
  • :design — tokens, components, icons

5. Data Model

// MonitoredApp
data class MonitoredApp(
  val id: String,            // package name
  val name: String,
  val iconBitmap: Bitmap,
  val permissions: List<Sensor>,
  val risk: Risk,            // SAFE | WARN | DANGER
  val accesses24h: Int,
  val backgroundPct: Int,    // 0..100
  val installedAt: Instant,
  val lastAccessAt: Instant,
)

enum class Sensor { MIC, CAM, GPS, KEYBOARD, WIFI, BLUETOOTH }
enum class Risk { SAFE, WARN, DANGER }

// AccessEvent (Room entity)
@Entity(tableName = "access_events")
data class AccessEvent(
  @PrimaryKey(autoGenerate=true) val rowId: Long = 0,
  val packageName: String,
  val sensor: Sensor,
  val startedAt: Instant,
  val endedAt: Instant?,         // null while live
  val foreground: Boolean,
  val durationMs: Long?,
)

6. Risk Scoring

Computed per app on every monitor tick. Pure function, easy to unit test.

fun risk(app: MonitoredApp, recent: List<AccessEvent>): Risk {
  val bgAccess = recent.count { it.packageName == app.id && !it.foreground }
  val sensitiveBg = recent.any {
    it.packageName == app.id && !it.foreground &&
    it.sensor in setOf(MIC, CAM, GPS)
  }
  return when {
    sensitiveBg && bgAccess >= 5 -> DANGER
    bgAccess >= 3 || sensitiveBg -> WARN
    else -> SAFE
  }
}

7. Privacy Index

Single 0–100 score on the dashboard ring. Weight by sensor severity:

privacyIndex =
  100
  − 4  × (number of DANGER apps)
  − 1  × (number of WARN apps)
  − 0.5× (background mic/cam events in last 24h)
  clamped to [0, 100]

8. The Hero Moment — Floating Bubble

Use Android's Bubble API (Notification + BubbleMetadata, API 30+). Anchor it to a BUBBLE_PREFERRED notification channel with high importance. Tapping opens AppDetailActivity with the offending package as extra. Pulse + radar animation only inside the in-app preview; the actual system bubble uses the OS chrome.

9. Foreground Service

Required so the monitor survives Doze. Type: FOREGROUND_SERVICE_DATA_SYNC + a low-importance "Watching apps" channel. Polls AppOpsManager every 10s; emits AccessEvents into Room. Battery budget target: < 1%/hr.

10. Onboarding Permission Flow

  1. Step 1 — pure marketing slide
  2. Step 2 — pure marketing slide
  3. Step 3 — CTA button launches ACTION_USAGE_ACCESS_SETTINGS. On return, check AppOpsManager.checkOpNoThrow(OPSTR_GET_USAGE_STATS, ...). If denied, show inline error and offer retry.
  4. After grant: also request POST_NOTIFICATIONS + SYSTEM_ALERT_WINDOW.

11. Acceptance Criteria

  • Bubble appears within 2s of any background mic/cam access.
  • App list scrolls 60fps with 250+ apps.
  • Battery usage in normal monitoring: ≤ 2%/24h.
  • All UI works offline — no network calls in v1.
  • Event log auto-prunes > 30 days.
  • No analytics, no telemetry — privacy promise.
